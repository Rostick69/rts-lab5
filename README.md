## Функциональные возможности

- Читает одну строку параметров из CSV и проверяет значения перед расчётом. Параметры хранятся в классе `Parameters`, объявленном через `@dataclass`.
- Для каждой конфигурации проверяет устойчивость. При перегрузке выводит причину и переходит к следующему расчёту.
- Для устойчивой системы вычисляет среднее число заявок в очереди и в системе, время ожидания и полное время пребывания. Для одного процессора также выводит вероятность простоя.
- Рассчитывает вероятность ожидания по формуле Эрланга C и вероятность превышения порога до начала обработки.
- По средней наработке и длительности ремонта определяет долю времени, когда узел готов к работе.

## Краткие теоретические сведения

В модели M/M/n заявки поступают пуассоновским потоком с интенсивностью λ. Каждый из n одинаковых процессоров обслуживает в среднем μ заявок в секунду. Если все процессоры заняты, заявка встаёт в общую очередь. Первой из очереди выходит заявка, поступившая раньше остальных.

| Величина | Расчёт |
|---|---|
| Загрузка одного канала | `ρ = λ / (nμ)`. Стационарный режим существует при `ρ < 1` |
| Вероятность ожидания C | Для M/M/1 равна ρ. Для M/M/n вычисляется по формуле Эрланга C |
| Среднее ожидание в очереди | `Wq = C / (nμ − λ)` |
| Среднее время в системе | `W = Wq + 1/μ` |
| Число заявок в очереди и в системе | `Lq = λWq` и `L = λW` |
| Вероятность ждать дольше D | `P(Tq > D) = C · exp[−(nμ − λ)D]` |
| Готовность узла | `Kг = MTBF / (MTBF + MTTR)` |

Порог D отсчитывается от поступления заявки до начала обработки. Задержки рассчитываются для работающего пула, а коэффициент готовности характеризует долю рабочего времени всего узла.

## Входные данные

Файл варианта — [variant2.csv](data/variant2.csv).

```csv
lam,mu,n,deadline,mtbf,mttr
8,5,3,0.2,1200,4
```

| Поле | Значение для варианта 2 |
|---|---|
| `lam` | В узел поступает в среднем 8 заявок/с |
| `mu` | Один процессор обслуживает в среднем 5 заявок/с |
| `n` | В пуле 3 процессора |
| `deadline` | Допустимое ожидание в очереди — 0,2 с |
| `mtbf` | Средняя наработка узла между отказами — 1200 ч |
| `mttr` | Среднее время восстановления — 4 ч |

## Пример работы

```console
python src/main.py
```

```text
Набор данных: variant2.csv

Один процессор, M/M/1
Загрузка: 1.6000
Система неустойчива. Стационарных показателей нет.

Пул процессоров, M/M/3
Загрузка: 0.5333
Система устойчива.
Вероятность ожидания: 27.3797%
Средняя длина очереди: 0.312911 заявок
Среднее число в системе: 1.912911 заявок
Среднее ожидание: 0.039114 с
Среднее пребывание: 0.239114 с
Вероятность ожидания дольше 0.2 с: 6.7517%

Готовность узла: 99.6678%
Средняя доля времени в восстановлении: 0.3322%
```

Один процессор успевает обслужить в среднем 5 из поступающих 8 заявок в секунду, поэтому очередь растёт. У трёх процессоров суммарная производительность составляет 15 заявок/с. В такой конфигурации **27,38 %** заявок попадают в очередь, а **6,75 %** всех поступивших заявок ждут дольше 200 мс. Среднее ожидание составляет **39,1 мс**.

## Проверка на контрольном примере

В [control.csv](data/control.csv) заданы один процессор, поток 3 заявки/с и скорость обслуживания 5 заявок/с. При `n = 1` одноканальная формула и многоканальный расчёт Эрланга дают одинаковые характеристики очереди.

```console
python src/main.py data/control.csv
```

| Показатель | Ручной расчёт | Вывод программы |
|---|---|---|
| Загрузка | 3 / 5 | 0,6000 |
| Среднее пребывание | 1 / (5 − 3) | 0,500000 с |
| Среднее ожидание | 0,6 / (5 − 3) | 0,300000 с |
| Средняя длина очереди | 3 × 0,3 | 0,900000 заявки |
| Вероятность ждать дольше 0,2 с | 0,6 × exp(−2 × 0,2) | 40,2192 % |
| Готовность узла | 1000 / (1000 + 5) | 99,5025 % |
